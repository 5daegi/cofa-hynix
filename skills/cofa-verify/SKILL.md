# 실행 증거로 완료 여부 판단하기

실행하지 않은 검사를 통과로 보고하지 않는다. 테스트 통과와 요구사항 충족을 구분한다. 제출 후 AI 이용 금지 문답 단계에는 적용하지 않는다.

## 1. 기준과 범위 확인

최신 과제 요구사항, 사용자가 확정한 업무 정책, 지정된 제출물을 읽는다. 요구사항마다 구현·산출물의 위치와 확인 방법을 연결한다. 기존 테스트가 있다는 이유로 모든 요구가 검증됐다고 가정하지 않는다.

검증의 기대값은 명세·담당자 답변·독립적인 계산·원본 데이터에서 가져온다. 구현과 같은 잘못된 가정을 복제한 테스트만으로 적합성을 판단하지 않는다.

## 2. 실제 검사

- 프로젝트 설정과 실행 환경에서 가능한 명령을 확인한다. 빌드·테스트·타입 검사 등이 실제로 존재하고 관련 있을 때 실행한다.
- 구현 중에는 변경 영향에 맞는 검사를 실행한다. 최종 제출 전에는 과제의 필수 검사와 관련 전체 테스트를 가능한 범위에서 실행한다. 시간이 부족하면 미실행 범위와 위험을 명시하고 제출 판단을 사람에게 남긴다.
- 명령, 입력·조건, 기대 결과, 실제 결과, 종료 상태를 확인한다. 로그 일부만으로 전체 성공을 추정하지 않는다.
- 최신 관련 코드 변경 이후의 결과를 사용한다. 코드·입력·환경이 바뀌지 않았다면 같은 대화에서 이미 확보한 결과를 재사용할 수 있다. 재사용한 결과와 해당 버전·시점을 밝히고 다시 실행했다고 쓰지 않는다.
- 정상 동작 외에 핵심 실패·경계 사례를 확인한다. 데이터 과제라면 행 수, 누락, 중복, 합계, 변환 규칙을 해당 요구에 맞춰 대조한다.
- 화면 조작이 필요한 항목은 사람에게 수동 확인 절차와 기대 결과를 제공한다. 자동 화면 조작을 실행하지 않는다. 사용자 보고와 AI가 직접 실행한 증거를 구분한다.

도구 부재, 권한, 네트워크, 시간 제한으로 실행하지 못하면 '미검증'으로 남긴다. 실패를 해결하려고 검사를 무력화하거나 결과를 꾸미지 않는다.

## 3. 결과표

| 요구사항 | 구현·산출물 위치 | 검증 방법·입력 | 실제 결과·근거 | 상태 |
| --- | --- | --- | --- | --- |
| 실제 요구사항 | 실제 경로 | 실제 수행 내용 | 실제 출력 또는 미실행 사유 | 충족 확인 / 실패 / 미검증 / 미구현 |

일부 검사만 통과했다면 그 범위만 통과했다고 보고한다. 실행 실패와 기능 오류를 구분한다. 다른 에이전트의 완료 보고는 직접 증거를 확인하기 전까지 검증 결과로 취급하지 않는다.

## 4. 최종 보고와 이해 확인

다음 네 항목을 짧게 보고한다.

1. 완료한 필수 기능과 검증 근거.
2. 실패·미검증·미구현 항목 및 실제 영향.
3. 사용자가 선택한 방식과 AI가 위임받아 선택한 방식, 그 근거.
4. 제출 대상 파일·실행 방법·남은 한계.

과제 작업 단계에서만 실제 코드·결과에 관한 이해 확인 질문을 제안할 수 있다. 사용자가 답하기 전에 이해했다고 기록하지 않는다. 사람의 결정이나 검증 기록을 사후에 만들어내지 않는다.

최종 제출은 사람이 수행한다. 본 스킬이 제출 버튼을 누르거나 제출 후 문답을 대신하지 않는다. 이 문서에 따랐다는 이유로 점수·합격·모든 숨은 테스트 통과를 보장하지 않는다.
